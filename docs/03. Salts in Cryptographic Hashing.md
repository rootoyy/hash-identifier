A Salt is a unique, randomly generated string of characters combined with a user's password before running it through a cryptographic hash function

## The problem it solves
If two users happen to choose the exact same password, and the system uses a plain hash function 

$$\text{MD5}("hunter2") = \text{f52fbd32b2b3b86ff88ef61f3d728045}$$
Both users will have the exact same hash string stored in the database. This exposes the application to two major vulnerabilities: 
- Pattern recognition: An attacker with access to the database can instantly identify users sharing the same password
- Rainbow tables: Attackers leverage precomputed lookups tables containing billions of plaintexts alongside their corresponding hashes. Cracking a stolen hash becomes as fast as performing a simple database query
## How salting works

When a user creates or updates their password, the application executes the following workflow:
1. Generation: Create a unique, pseudo-random string for that user
2. Concatenation: Combines the raw password with the salt
3. Hashing: Pass the combined string through the hashing algorithm
4. Storage: Save both the salt and the resulting hash in the database
$$\text{Final Digest} = \text{Hash}(\text{Password} + \text{Salt})$$
